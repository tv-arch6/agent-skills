# محرك مشغّل Cigram — التقرير النهائي

> هذا المجلد يحتوي على كل ما أُنجز: كود المحرك (Java)، سكربت يدمجه في مشروع Cigram، اختبارات، وWorker صغير لحماية مفتاح قاعدة البيانات.
> المشروع المعدَّل جاهز للاستيراد في Sketchware في `dist/` (ملف `.swb` لا يُرفع إلى git بسبب حجمه، 28 ميغابايت).

## 1. ما الذي فُحص وما القرار المعماري

| | filmsandseries (`com.Cigram.vid`) | NewProject (`com.my.newproject`) |
|---|---|---|
| ما هو فعلاً | تطبيق المشاهد: التفاصيل، المشغّل (ExoPlayer 2.19.1)، «شاهد مع صديقك»، البحث، Cast | **لوحة إدارة**: إضافة أفلام/مسلسلات، رفع فيديو وترجمة، إعلانات، إحصاءات |
| المشغّل | `PlayerActivity` (ExoPlayer)، `CigramTogetherPlayerActivity`، `CigramLivePlayer` | `CgPlayerActivity` = شاشة **اختبار** بـ `VideoView` للمشرف، بلا ExoPlayer ولا غرف ولا أزرار المشاهد |
| الاستخدام هنا | **هو الأساس**: كل التعديلات عليه | **مرجع فقط** (ترقيم المواسم والحلقات، تحويل ترميز الترجمة، مسارات TMDB في الـ Worker) |

**لماذا لم يكن NewProject نقطة البداية؟** الطلب نصّ على الأخذ به «ما لم يكشف الفحص سبباً تقنياً واضحاً». السبب: هو تطبيق المشرف وليس فيه مشغّل المشاهد ولا الغرف ولا صفحة التفاصيل ولا زر «شاهد الآن». لم يُعدَّل ولم يُنقل منه أي كود، ولم تُستورد منه بيانات أو أسرار.

نتائج الفحص التي بُني عليها العمل (مأخوذة من الملفات لا من الافتراض):

* مسار «شاهد الآن»: `DetailsActivity` ← `CigramStage1InitProvider.watchNowWithAd` ← `openPlayerForTitleItem(...)` ← `PlayerActivity`. إذا لم يكن للعنصر رابط، كانت النتيجة سابقاً رسالة «رابط الفيديو غير متوفر» فقط. **هذه هي نقطة الربط.**
* `PlayerActivity` كود مضمَّن داخل بلوك Sketchware (157 كيلوبايت)، يمرّ كل تحميل فيديو عبر `MediaLoader.load(video, subtitle, position)`. الترجمة كانت رابطاً واحداً يُمرَّر لـ ExoPlayer كـ `SubtitleConfiguration` (تغييرها يعني إعادة تحميل الفيديو).
* المشغّلان لا يستعملان `Player.Listener` عمداً (تعليق في الكود: D8 في Sketchware ينهار داخل `ListenerSet`) ← **المحرك كله يعتمد الاستطلاع (polling) ولا يسجّل أي Listener.**
* غرف «شاهد مع صديقك»: الخادم يحفظ **مرجع المحتوى فقط** (`content_id` + الموسم + الحلقة) وكل جهاز يحلّ رابطه من مكتبته. لم يُغيَّر البروتوكول.
* `PlayerActivity.onStop` يحرّر المشغّل ويغلق الشاشة إذا فقدت التركيز؛ فتح منتقي الملفات كان سيغلق المشغّل ← عُولج بـ `CigramSubtitlePickActivity.isPicking()`.
* ملف `compile_log` داخل التصدير يحتوي أخطاء قديمة (`cgGlass cannot be resolved` في `DetailsActivity`) **سابقة لعملي** ولم ألمسها.

## 3. حالة المزوّدين

| المزوّد | الحالة | السبب / ما ينقص |
|---|---|---|
| مكتبة Cigram (روابط R2 / الخادم الخاص) | **متكامل** | يقرأ رابط **تلك الحلقة بالذات** من المكتبة (موسم + رقم)، لا يعيد رابط حلقة مجاورة أبداً. اختُبر آلياً. |
| vidfast.vc | **يحتاج API** | لا توثيق ولا واجهة تكامل في المشروعين، والموقع غير قابل للوصول من بيئة العمل (الاتصال مرفوض)، فلم يمكن فحصه. لا رابط مُختلق. |
| vidnest.fun | **يحتاج API** | نفسه |
| videm.xyz | **يحتاج API** | نفسه |
| vidbolt.pro | **يحتاج API** | نفسه |

كل واحد منها مسجَّل كـ Adapter مستقل (`CigramJsonProvider`) يعلن حالته `NEEDS_API` ويشرح ما ينقصه في التشخيص، ولا يُنتج أي رابط. يتحول إلى «متكامل» دون تعديل كود عند ضبط عنوان واجهة **مصرّح بها** له (`provider.<id>.api` و`provider.<id>.token` في إعدادات التطبيق الخاصة) تُرجِع JSON بالصيغة الموثّقة أعلى `CigramJsonProvider`. إن كان واجهة مزوّد ما بصيغة مختلفة فيكفي توريث الصنف وتعديل `buildUrl`/`parse` فقط.

ملاحظات:
* مصدر من نوع «صفحة تضمين فقط» يُوسَم `EMBED_ONLY` وغير قابل للتشغيل: أزرار المشغّل الأصلية لا تتحكم بمشغّل صفحة خارجية، لذلك لا تُضمَّن صفحة ويب داخل المشغّل ولا يُدَّعى التحكم بها.
* لا تجاوز لتسجيل دخول أو CAPTCHA أو DRM أو ترويسات. استعمال أي مزوّد خارجي مسؤولية صاحب التطبيق ويجب أن يكون وفق ترخيص المحتوى وشروط المزوّد.
* TMDB يعطي **بيانات وصفية فقط** (عناوين، ملصقات، مواسم، حلقات)، ولا يعطي روابط فيديو. شروطه تطلب عبارة: *This product uses the TMDB API but is not endorsed or certified by TMDB.* (تظهر أسفل شاشة البحث).

## 4. نتائج البناء والاختبار (حقيقية، وما لم يتحقق مذكور)

تُشغَّل كلها بأمر واحد:

```bash
LIBS=<مجلد فيه android-all.jar و junit-4.13.2.jar و hamcrest-core-1.3.jar> \
SWB=<ملف filmsandseries الأصلي .swb> \
cigram-player-engine/verify/verify-all.sh
```

| الفحص | النتيجة |
|---|---|
| اختبارات JUnit لنواة المحرك (JVM + خوادم HTTP محلية) | **105 اختباراً ناجحاً**، تكرّر التشغيل 3 مرات بلا تذبذب |
| اختبارات ملتصقة بـ ExoPlayer (تخطيط نص الترجمة، حجم JSON الحلقات) | **6 ناجحة** (على stubs) |
| اختبارات الـ Worker (Node، TMDB مُحاكى) | **10 ناجحة** (وجدت خطأً حقيقياً: بحث بلا `query` كان يُقبل، أُصلح) |
| ترجمة (compile) الكود الملتصق بـ ExoPlayer وكود التطبيق | **تنجح مقابل stubs فقط** — 141 صنفاً |
| فحص بلوكات Sketchware المعدّلة (`PlayerActivity`, `SearchXmlActivity`) وملفَّي Java المعدّلين مقابل الأصل بـ javac | **0 أخطاء صياغة، 0 أخطاء جديدة**؛ والفحص نفسه يفشل فعلاً إذا أُدخل خطأ متعمَّد (جُرّب) |
| سلامة الملف النهائي | 207 ملفاً بلا تغيير byte-for-byte، 4 معدّلة، 34 مضافة، 3 أسطر فقط تغيّرت في `logic`، الـ zip سليم |

**ما لم يُنفَّذ ولم يُتحقق منه** (يجب أن يُقال بوضوح):

* **لم يُبنَ المشروع في Sketchware** ولم يُشغَّل على جهاز أو محاكي. لذلك: واجهات الشاشات، الدوران، العودة إلى التفاصيل، الخروج وإعادة الفتح، PiP، Cast، تحرير الموارد الفعلي، وسلوك D8 — **غير مُتحقَّق منها على جهاز**.
* **لم أستطع تنزيل مكتبات ExoPlayer 2.19.1** (سياسة شبكة البيئة تمنع مستودع Google Maven). كود الملتصق بـ ExoPlayer مُترجَم فقط مقابل واجهات كتبتُها بيدي لما يستعمله (`verify/stubs/`، وفيها README يوضح أنها ليست المكتبة الحقيقية). الاستدعاءات المستعملة معروفة في 2.19 لكن **التأكيد النهائي عند أول بناء حقيقي**.
* **مواقع المزوّدين الأربعة وTMDB غير قابلة للوصول من بيئة العمل**: لم تُفحص وثائقها، واختبارات TMDB تمت على خادم محلي يحاكي شكل ردوده. الشكل المستعمل (`search/multi`, `tv/{id}`, `tv/{id}/season/{n}`, `movie/{id}`) هو واجهة TMDB v3 المعروفة، لكن **لم يُجرَّب على TMDB الحقيقي**.
* التحقق من الفيديو يثبت أن الرابط وسيط فيديو حقيقي (HLS/DASH/MP4…) لكنه **لا يستطيع إثبات أن كل ترميز يُفَكّ على الجهاز**؛ هذه الكلمة الأخيرة لـ ExoPlayer، ولذلك يوجد الانتقال لمصدر آخر عند فشله في أول 10 ثوانٍ من التحميل (وهي نافذة حلقة الانتظار الموجودة أصلاً في المشغّل).

## 5. خطوات استيراد النسخة النهائية

1. خذ نسخة احتياطية من مشروعك الحالي في Sketchware.
2. Sketchware ← استيراد مشروع ← `dist/filmsandseries_v10.65_com.Cigram.vid_65_player-engine.swb`.
3. ابنِ المشروع. أي خطأ ترجمة يخصّ `cgGlass` في `DetailsActivity` موجود في التصدير الأصلي ولا علاقة له بالمحرك. إن ظهر خطأ في استدعاء ExoPlayer من ملفات `CigramSubtitleOverlay` / `CigramPlayerBridge` فأرسله لي: هو أول مكان يجب أن أراه فيه.
4. انشر الـ Worker (`worker/DEPLOY_AR.md`) ثم من شاشة «ابحث في الفهرس العالمي» **اضغط مطوّلاً على العنوان** وضع العنوان `https://<worker>/3`.
5. (اختياري) مزوّد مصرّح به: ضع `provider.<id>.api` و`provider.<id>.token` (نفس الشاشة تعرض حالة كل مزوّد).

لإعادة توليد الملف من ملفك الأصلي: `python3 patches/apply_patches.py --swb <الأصل> --out <الناتج>`. السكربت يتوقف دون كتابة أي شيء إذا لم يجد أي «مرساة» نص مرة واحدة بالضبط (أي إذا تغيّر مشروعك).

## 6. قائمة الأعمال المتبقية والقيود

1. **بناء الشاشة على جهاز حقيقي** وتجربة السيناريوهات المعلّمة ⚠️ أعلاه.
2. **غرف المشاهدة الجماعية لعمل من الفهرس العالمي غير مدعومة**: الغرفة تحلّ الرابط من مكتبة كل جهاز، والخادم الذي يخزن الغرف (`together-worker`) غير موجود في التصديرَين، فلم أغيّر البروتوكول. العمل الذي ليس في المكتبة يظهر فيه الخطأ الحالي «غير متوفر على جهازك». لدعمه يلزم أن يقبل الخادم حقل مزوّد/مصدر داخل `content`.
3. المزوّدون الأربعة: ينتظرون **واجهات مصرّحة وتوثيقاً**.
4. DASH: يُتحقَّق من المانيفست فقط (دون مقاطع)، وSmooth Streaming غير مدعوم. DRM لا يُشغَّل.
5. ترجمة الملف الخارجي لا تُرسل إلى Chromecast (البث يحتاج رابط ترجمة عام).
6. الانتقال التلقائي لمصدر آخر يغطي فشل التحميل الأول فقط؛ فشل لاحق أثناء المشاهدة يعالجه المشغّل كما كان.
7. واجهة الإعداد (العنوان/المفتاح) بسيطة ومخفية للمطوّر؛ شاشة إعدادات رسمية لو أردت.
8. `http` المجرّد: يعمل لروابط ترجمة المكتبة (كما كان) لكنه يخضع لسياسة Android للنقل غير المشفّر في تطبيقك.

## 7. الأدمن: «من المزوّد» بروابط مباشرة واحتياطية (تحديث)

* **فيلم:** في «ملف الفيلم» تبويب ثالث «من المزوّد» ← «جلب الروابط من المزوّدين». يسأل كل مزوّد مضبوط بمعرّف TMDB/IMDb للفيلم المختار، ويفحص كل رابط بنفس فاحص تطبيق المشاهد (فيديو حقيقي لا صفحة، ويتجاهل DRM وصفحات التضمين). أول رابط يعمل يصبح `video`، والبقية تُحفظ في `video_backups` (رابط بكل سطر).
* **مسلسل:** «إضافة موسم كامل» ← زر «جلب روابط الموسم من المزوّدين (بدون رفع)». الخادم يعطي حلقات الموسم من TMDB (`POST /admin/tmdb/season`)، وكل حلقة تُطلب من المزوّدين وتُفحص، ثم تُنشر الحلقات الجاهزة دفعة واحدة مع احتياطيّها.
* **التطبيق:** يشغّل الرابط في مشغّله الأصلي بكل الأزرار والإعدادات والغرفة. إن فشل الرابط ينتقل وحده إلى الاحتياطي التالي **لنفس الفيلم/الحلقة**.
* **المزوّد** = خانة (اسم + عنوان API بـ https + مفتاح) من «إعداد المزوّدين». الـ API يجب أن يكون مرخّصاً ويعيد **روابط مباشرة** بهذه الصيغة:
  `GET {api}/resolve?type=movie|episode&tmdb=..&imdb=..&title=..&year=..&season=..&episode=..` مع `Authorization: Bearer {key}` ← `{"sources":[{"url":"https://…/index.m3u8","type":"hls|mp4|dash","quality":"1080p","headers":{…}}]}`.
  مزوّد بواجهة مختلفة يحتاج محوّلاً صغيراً (أو Worker وسيط) — أرسل توثيقه.
* **يجب نشر الـ Worker المعدّل** (`dist/cigram-admin-worker-v2.js`): يضيف `video_backups` ومسار حلقات الموسم. بدونه يُرفض النشر.
* التحقق: كل كود Java في الأدمن (القديم + الجديد) يُترجم كاملاً مقابل android-all بلا أي خطأ جديد (3 أخطاء سابقة في ملفات أخرى لم تُلمس)؛ الـ Worker صياغته سليمة؛ 111 اختبار JVM ناجح، منها الانتقال إلى الرابط الاحتياطي. لم يُجرَّب على جهاز ولا على مزوّد حقيقي.
